新建项目

先写一段说明，派一位你信任的 Agent 把它整理成项目约定（受众、要讲清的几件事、篇幅、风格、不做什么）。它只起草约定，不写内容；草案你逐节改过、确认后才生效，之后的任务照常按规则派发。

起草者 会调用一次模型，计入这个项目的调用次数

项目约定（project.md）

每个任务包都会原样带上它：只写所有参与者都必须遵守的内容。改了以后，之后派出的任务用新版；已经派出的任务按当时的版本（任务包里存着当时实际发送的内容）。旧版本存档，按项目设置留档进 git。

参数（protocol.json）

只写要改的项，其余沿用默认值。调用次数、费用这类上限可以调，不能取消；不合法的写法会被拒绝，文件不动。

阶段

        

        
 

        
切换时程序从正式记录生成一页以内的交接单（不调用模型）；旧阶段的工作记忆先归档再清空，新阶段换一个记忆空间。新阶段的任务包只带交接单，不带此前的讨论。这一轮还没收轮时不能切换。

        

      

      

        
自动调度

        

          
          
        

        
默认关。打开后按分工表（routing）持续派发已就绪的任务，受调用次数和费用上限约束；“跑一轮”只把当前已就绪的任务派一次。冷却中、手上还有任务的参与者不派。揭晓、选定这些决定仍由你做。

        

      

      

      

      

    


    

      

        
发起分工

        
把一组输入拆成互不重叠的几份，轮流分给选中的参与者，每份一个子任务并立即派发。子任务只能写自己那一份：改动或引用别的部分的记录、新建与已有来源同一地址的来源卡，提交入口都会拒绝。

        

          
          
          
        

        

        
        

        

      

      

    


    

      

        
发起竞争

        
几位起草者同时独立起草（密封，完成前互不可见）→ 揭晓 → 匿名评审（每条意见必须指向具体的节、页或论断编号，指不到的退回）→ 你选定一份 → 落选方案里值得保留的内容写成移植补丁，逐条接受或拒绝 → 书记只应用通过的补丁。

        

          
          
          
          
        

        

        
 

      

      

      

    


    

      

        
导出

        
把幻灯片（slides/）导出为 Markdown 和 PPTX。正文每个句子要带论断编号（例如 C001），或标为〔非事实〕；导出时编号从页面上去掉，PPTX 里挪进讲者备注，Markdown 里写成脚注。每次导出写成一条导出记录（EX###），文件随 git 留档；幻灯片改版后，这份导出变成“待更新”。

        

          
          
          
          
          
          
        

        
交给 Agent 时，它不拿工具，只按幻灯片、模板的版式清单和 skill 回一份版式方案；PPTX 仍由脚本生成，检查也一样。模板放在 templates/pptx/，skill 放在 templates/skills/，换模板或 skill 不用改代码。

      

      

      

      

    


    

      

      

        
你填的数值

        
程序算不出来的两项：从初稿到你愿意分享花了多少时间，以及你抽查发现的实质错误（事实错误、出处错误、引文不支持结论等；措辞和排版不算）。

        

          
          
        

        
        
        

      

    


    

      

        
在这个项目里开研讨

        

        
        
        
 记忆用这个项目自己的空间（工坊·项目名·研讨），与别的项目、全局共享记忆互不影响。
