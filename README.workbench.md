# WETALK 工坊（WETALK-WORK）

从 [WeTalk](https://github.com/Ramirez0291/wetalk) 派生的多 Agent 内容生产工坊。WeTalk 本身保持轻便，工坊功能只在这个仓库里开发；WeTalk 设为 `upstream` 远程，按需同步修复：

```bash
git fetch upstream
```

设计与开发文档在 `dev-lib/`：先读 `workbench-design-v2.md`（为什么），再读 `workbench-dev-spec-v0.2.md`（怎么做）。两者有出入时以开发文档为准。

## 运行

```bash
npm start
```

- 本地配置 `wetalk.config.json` 默认用 7790 端口，可以和 WeTalk（7788）同时运行。
- 项目资料目录默认是本仓库下的 `projects/`（`workbench.defaults.json` 的 `projectsDir`，或环境变量 `WETALK_PROJECTS`）。它是一个独立的 git 仓库，本仓库忽略它；服务启动时如果它还不是 git 仓库会自动初始化。
- 服务进程是 `projects/` 里正式记录的唯一写入者。

## 工坊页面

服务启动后打开 `http://localhost:7790/`（工坊是主页面；研讨室在 `/talk`，旧地址 `/workbench` 仍可用）。页面按要做的事分成五组，组里再分页：

- **首页**
  - **下一步**：按当前阶段给出一件要做的事，就在这里开始（见下文“首页：下一步”）；下面是待你决定的前几项、项目约定填了没有、进展统计。
  - **待你决定**：服务进程之外改过的记录文件、读不出的记录文件、git 留档失败，以及各模块要你处理的事。
- **工作**
  - **任务**：新建、派发、取消任务，看任务包。
  - **分工**、**竞争**：两种工作方式（见下文“分工与竞争”）。
  - **调度与阶段**：七步阶段与交接单、自动调度开关与“跑一轮”、轮次结论、冷却中的参与者（见下文“调度与阶段”）。
- **资料**
  - **记录**：每条记录的派生状态（新鲜度、核验状态、阻塞、可进入成品）、上下游、历史版本和内容来源（provenance）。
  - **追溯**：输入页面、论断或来源编号，看页面 → 论断 → 来源 → 原文位置；按论断引用时的来源版本核对引文。
  - **研讨**：这个项目里开的研讨议题；从记录详情点“开研讨”会带上那条记录的内容，开好后进入研讨室。
- **成品**
  - **导出**：Markdown 与 PPTX 导出、结构检查、读回核对、渲染检查、逐页视觉检查（见下文“导出与成品检查”）。
  - **报告**：试运行报告，与单 Agent 基线逐项对比（见下文“试运行报告”）。
- **约定与系统**
  - **项目约定与参数**：在页面上改 `project.md` 和 `protocol.json`（见下文“新建项目与项目约定”）。
  - **提交与留档**：每次提交分开显示“数据已提交”和“留档已完成 / 待重试 / 失败”。
  - **候选稿**：以主持人身份提交改动（先存为候选稿，再点“晋升”）。

右上角“＋ 新建项目”打开新建项目向导；还没有任何项目时，打开页面就是向导。

## 新建项目与项目约定（WP8）

- **新建项目向导**：
  1. 填项目名和一段说明（给谁看、看完应当明白什么、大概多长、风格要什么不要什么），选一位起草者，点“新建并起草约定”；也可以点“新建，我自己填”。
  2. 起草者把说明整理成约定的各节，草案按节合并进约定，标“草案”的节是它写的；它想跟你确认的问题列在上面。逐节改好后点“确认约定，开始收集来源”：约定写入 `project.md`，阶段切到“收集来源”，回到首页。
- **起草者只出草案**：
  - 任务类型 `plan_project`，可见性 `plan`：你的说明和现在的约定（含模板引导语）内联，不给工具。会调用一次模型，计入项目的调用次数。
  - 草案不进正式区，也不直接写进 `project.md`，只记在任务上；你确认之前，任务包里用的仍是原来的约定。
  - 它不写内容、不派任务。之后的任务照常由你发起、按分工表由规则派发，核验者照常由规则挑选。
  - 只能由向导或约定页发起（`POST /plan`）；手动新建这类任务会被拒绝，外部会话不能认领，自动调度也不派它。
  - 回复不合格式（没有 json、没有一节对得上约定）时这次尝试失败，并写明原因；对不上约定的节列出来，不合并。
  - 草案记着它按哪一版约定合并。之后约定改过（包括你已经确认），这份草案就算过时，首页不再提示“待确认”。
- **在页面上改约定和参数**（“约定与系统 → 项目约定与参数”）：
  - **约定**：每节一个输入框，模板里的引导语作占位提示；没改过的节原样写回。也可以切到“直接改 Markdown”。
  - **参数**：常改的几项（调用次数和费用上限、每页字数、竞争份数、核验份数、高峰时段、自动留档）做成表单，其余直接改 JSON。保存前按默认参数合并校验，不合法时文件不动。
  - **不覆盖别处的改动**：页面打开时记下文件的 hash，保存时带回去；期间文件被改过（包括在服务之外直接改），保存被拒绝，页面上可以载入最新版再改。
  - **旧版本**存到 `<项目>/archive/versions/_project/`（不进 git）；按项目设置留档进 git；`events.jsonl` 记一条 `setting_changed`。
  - **已派出的任务不受影响**：任务包里存着当时实际发送的提示词（含约定）。之后派出的任务用新版。
- 页面上还会标出约定里没填的节：去掉引导语后什么都没有，或“页数：”这类键后面没写值。

## 首页：下一步（WP8）

首页按当前阶段给出一件要做的事。每个按钮调用的都是各页原来的同一个接口，规则、上限和身份检查都不变，首页只是把它们按顺序摆出来：

| 阶段 | 首页上能做的事 |
| --- | --- |
| 还没开始 | 约定没填：让 Agent 起草，或自己填；填好了：开始收集来源 |
| 收集来源 | 按网址抓取（每行一个，DeepSeek Fetch）；搜索（起草者建议的关键词一点就搜，结果只是线索，抓取原文后才算来源）；手工录入来源卡（标题、出处或网址、正文快照） |
| 抽取论断 | 把全部来源分给勾选的参与者抽取论断（默认勾上分工表里做 extract 的）；给还缺核验的论断派对抗核验（已有核验在路上的不重复派） |
| 大纲、讲稿 | 发起竞争（默认起草者取分工表里的 outline / key_writing），输入是可进入成品的论断，讲稿另加最新的大纲；进行中的竞争一键打开 |
| 幻灯片 | 还没有自动化：去候选稿录入 |
| 审阅 | 导出 Markdown 和 PPTX，打开最近一次导出做渲染检查与终审 |

每一步下面都有“下一步：某阶段 →”。条件不满足时按钮是灰的（例如还没有来源卡、还没有可进入成品的论断）。

## 提交与恢复（契约二）

- 正式记录只经提交入口写入：`POST /api/projects/:p/submissions` 收稿为候选稿，`POST /api/projects/:p/submissions/:sid/promote` 在仓库级串行队列里晋升。
- 没有任务号的提交只接受工坊页面的主持人入口（页面里带有每次启动重新生成的令牌）；带任务号的提交在 WP4 的任务系统之前一律返回“任务不存在”。
- 事实来源是正式记录文件 ＋ `projects/commits.jsonl`。晋升先写 `_txn/<提交编号>/` 清单，再归档旧版本、逐个替换文件、追加 applied；启动时按清单补完未完成的提交。
- 启动时在 `projects/` 建 `.workbench.lock`，已有存活的服务（或正在本地新建项目的命令行工具）就拒绝启动。
- git 留档从 blob 取确切字节、用临时索引提交，只包含本次清单里的文件，不动工作区和你已暂存的改动；失败后每 60 秒重试，按提交编号顺序补交。
- 写入出错且就地重做也失败时，服务进入“写入故障”状态，拒绝一切写入，直到重启时把那次提交做完。
- 服务进程之外改过或删掉的记录文件不会被采纳：页面和追溯显示的仍是已提交的内容，它和下游标为待更新，涉及它的晋升被拒绝。
- **git 不是完整备份。** 提交日志、候选稿、旧版本副本和 blob 不进 git。备份或迁移项目时，要保留整个 `projects/` 目录。

## DeepSeek（WP3）

- 密钥只从环境变量 `DEEPSEEK_API_KEY` 读取，不写进任何配置文件。PowerShell 里：

  ```powershell
  $env:DEEPSEEK_API_KEY = (Get-Content .\DeepSeek-devAPIKEY.txt -Raw).Trim(); npm start
  ```

  开发用密钥文件已被 `.gitignore` 忽略，不要提交。
- 研讨室参与者：在 `wetalk.config.json` 里加 `{"id":"deepseek","name":"DeepSeek","adapter":"deepseek","model":"deepseek-flash","effort":"high"}`（`effort` 可选 none / low / high / max）。它走 API，没有命令行；有密钥就显示为可用，“停止”同样能中断。调用记录里有 `usage`（token 与按价目估算的美元）和每次尝试的状态。
- 重试：408、429、5xx 和网络错误按 `retry.delaysSec` 退避（有 `Retry-After` 时优先），其他 4xx 不重试。`deepseek.timeoutSec` 是整次调用（含重试）的总时限。
- 工坊接口：`POST /api/projects/:p/web/search`（只给线索，结果不能作为引文）、`POST /api/projects/:p/web/fetch`（`{url, source_id?, create?}`，正文存成来源快照）、`GET /api/projects/:p/usage`、`POST /api/projects/:p/sources/:id/availability`（主持人确认来源已不存在）。
- 用量账本 `projects/<项目>/usage.jsonl` 记每一次尝试（含失败与重试），项目的调用次数与费用上限（`budget`）按它累计；到上限后新调用和重试都被拒绝。费用要等返回才知道，最后一次调用可能略超费用上限。
- 价目在 `workbench.defaults.json` 的 `pricing`（高峰价，低谷按 `offPeakFactor` 折算；不识别中国节假日，一律按高峰估算，宁可高估）。价格变了改这里。
- 来源正文只有两个来处：Fetch 快照，或主持人在工坊页面手工录入。论断的引文必须能在所引来源版本的正文快照里找到（忽略 Markdown 的标点转义和空白重排），否则不能晋升。

## 任务（WP4）

- 工坊页面的“任务”标签：新建任务（类型来自 `modes`，另有 `anonymous_review`、`audience_reader`），派发给指定参与者，取消，处理“待你决定”，查看每次尝试的任务包，揭晓密封轮次。
- 状态：提出 → 可认领 → 进行中 → 已交稿 → 完成；另有失败（尝试次数用完）、已取消、待你决定（类型不允许、深度或预算超限）。租约默认 30 分钟，到期自动收回；迟到的旧结果存为历史草稿，不会覆盖新结果。
- 任务包存在 `projects/<项目>/archive/packets/`，记录当时实际发送的提示词、全部输入（按内容 hash）和有效配置，能完整还原。
- **可见性**：
  - Claude、Codex 和 DeepSeek 执行工坊任务时，输入一律写进提示词，不给任何工具。WP4 在本机实测过：只开读类工具的 Claude、开着 shell 的 Codex 都能读到工作目录以外的文件。
  - Codex 另外关掉内置应用、插件、浏览器、多 Agent、网络搜索等，并按 `--json` 事件审计：出现任何工具调用，那份稿子都标为“独立性未证明”。
  - 密封类任务（竞争起草、匿名评审、观众型读者）的结果在揭晓前只留在服务进程内存里；服务重启则本轮重跑。
- 命令行 Agent 的每次调用同样占项目的调用次数上限。
- MCP 新增工具：`wetalk_task_list`、`wetalk_task_claim`（返回租约凭证和任务包）、`wetalk_task_renew`、`wetalk_submit`、`wetalk_record_read`、`wetalk_trace`。外部会话的身份一律记为未证实；密封类任务不能由外部会话认领。`mcp.mjs` 默认连本仓库配置里的端口。
- 真实 Agent 的可见性实测脚本：`node tests/workbench/live/live-agents.mjs codex deepseek claude`（会真实调用，不在 `npm test` 里）。Codex CLI 升级后要重跑。

## 核验与异议（WP5a，契约一）

- **核验**：在“记录”里打开一条论断：
  - 点“派对抗核验”：自动挑与作者不同厂商、还没核验过当前版本的参与者，凑够还差的份数；也可以指定某一位。
  - 也可以自己核验：判“支持”时必须附来源正文里逐字出现的引文。
- **份数**：核心结论（`core: true`）要 2 位独立核验者，其他论断 1 位（`verify.coreClaimVerifiers` / `otherClaimVerifiers`）。
  - 按核验者去重：同一核验者只算最新一份；你算一位。
  - 与作者同厂商的核验直接被拒绝；MCP 外部会话（身份未证实）的核验保存但不计入。
  - 支持且份数够、没过期、没有阻塞异议，论断才“可进入成品”。
- **异议**：提出时选类别和指针。
  - 三类阻塞异议（来源不存在、数字错误、引文不支持结论）提为“待裁定”时，指针必须能核对（来源原文、失败的抓取记录、论断没有来源）；定位不到原文就提为“待补证”。
  - 状态：待裁定 → 成立 / 不成立（由作者和提出者之外、与作者不同厂商的核验者或你裁定），或转“待你决定”。
  - 成立的异议，要等论断改版并重新核验通过，才能转为“已解决”。提出者可以撤回；“待你决定”的只有你能裁决。
- **规则**：
  - 异议待补证时，自动生成补证任务（每个只做一次，最多 `evidence.maxAttempts` 个），用完仍定位不到就转“待你决定”。
  - 你确认来源已不存在（gone）时，对每条引用它的论断自动提出“来源不存在”异议；撤销确认时自动撤回。
- “待你决定”里新增：待你裁决的异议、核验结论不一致的论断。
- MCP 新增工具：`wetalk_verification_create`、`wetalk_objection_create`。

## 分工与竞争（WP5b）

- **分工**（“分工”标签页，`POST /divide`）：把一组输入（记录，或每行一项的条目）拆成互不重叠的几份，轮流分给选中的参与者，每份一个子任务并立即派发。
  - 只能用 `modes` 里是 `divide` 的任务类型（默认是收集来源、抽取论断、检查引用）。
  - 互不重叠由程序保证：拆分时每项输入恰好分到一份；晋升时提交入口拒绝子任务越出自己那一份的写入，例如改动或引用别的部分的记录、针对别的部分的核验或异议、新建与已有来源同一地址的来源卡。
  - 分到的条目整份作为任务输入（进任务包、内联进提示词），不放进任务说明；条目最多 500 项、合计 20 万字，goal 最多 3000 字，超出直接拒绝，不截断。
  - 每份的结果照常经提交入口写成来源卡和论断，“分工”标签页按份列出进度和写进正式区的记录。
- **竞争**（“竞争”标签页，`POST /compete`）：用于 `modes` 里是 `compete` 的类型（默认是选题角度、大纲、核心解释），份数是 `compete.drafts`（默认 2，最多 6：匿名评审的标签只有六个）。
  1. **密封起草**：几位起草者同时独立起草，揭晓前方案只在服务进程内存里。服务重启后方案随内存消失，点“派发还没开始的成员”重跑，几份方案仍在同一个密封轮次里。
  2. **揭晓**：方案按随机标签（方案甲、方案乙……）显示。独立性未证明的方案不参与比较；有效方案不足两份时只能取消。
  3. **匿名评审**：评审者不能是起草者。评审只拿到标签和去掉署名的正文，每节标题后标着〔第 n 节〕。每条意见必须指向某个方案的第几节（或第几页，按节计），或该方案里出现的论断编号。
     - 指不到位置的意见（没写位置、节号不存在、方案里没有这个论断、只有位置没有意见）会被退回，原文和原因都保留。
     - 标签与起草者的对应关系在评审全部结束后才公开。
  4. **选定**：由你选定一份，并写理由。选定的方案原样写成正式作品（大纲或讲稿），内容来源记为它的起草者，选定者另记。表决选择以后再接。
     - 作品引用的论断：发起时按输入快照固定“可引用论断”（输入里的论断，以及输入作品引用的论断，版本按输入）。正文里的论断编号按它绑定版本；对不上的编号会明确拒绝，不静默省略。
     - 选定与书记“先记下、再提交、后补记”：中途出错时，下一次读取按提交结果补齐；结果还确认不了时只能原样重试。这些候选稿只能由竞争自己晋升。
  5. **移植补丁**：把落选方案的一节（或其中逐字的一段）放到底稿某一节的前后、节首节尾，或整节替换；节号按底稿原来的分节。
     - 每条补丁都由你接受或拒绝，并留下记录；拒绝必须写理由，决定后不再改。
     - 互相冲突的补丁不能同时接受（整节替换的那一节不能再有别的节内改动）。
     - MCP 会话也可以提补丁，提出者记为未证实。
  6. **书记**：书记是规则，不是模型。它只应用已接受的补丁，底稿其余部分一个字不改。
     - 作品的作者集合会并上搬来原文的起草者。
     - 作品在竞争之外被改过时，书记不覆盖，返回冲突；这时竞争照样可以结束，没应用的补丁会记下来。
  7. **少数意见记录**：被拒的补丁连同理由、没被任何已接受补丁采纳的评审意见，以及落选方案原文，都留在竞争记录里。
  - 竞争的流程记录存在 `<项目>/competitions/K###.json`。它和任务一样由服务维护、不进 git，每一步都记在 history 里。
  - “待你决定”会列出每个竞争下一步要你做的事：揭晓、发起评审、选定、接受或拒绝补丁、应用。
- **研讨与工坊**：研讨室的议题可以挂到工坊项目上（`POST /api/threads` 带 `project`、可选的 `ref`）。
  - 挂了项目的议题，记忆默认用这个项目自己的空间“工坊·项目名·研讨”，和别的项目、全局共享记忆互不影响。
  - 研讨室里会显示所属项目，点一下回到工坊，打开引出它的那条记录（`/?p=项目&r=编号`）。

## 调度与阶段（WP6）

- **自动调度**（“调度”标签页）：
  - 按项目开关，默认关。打开后，规则循环按分工表（`routing`）持续派发已就绪的任务；“跑一轮”只把当前已就绪的任务派一次。
  - 调度只执行规则，不调用模型做派发判断：
    - 任务指派了谁就派给谁；否则按分工表找可用的参与者，跳过冷却中的和手上还有任务的（`scheduler.maxPerParticipant`，默认 1）。
    - 对抗核验的 `different_vendor`：逐个试，资格不够的换下一位。
    - 依赖没完成的任务不派；`offPeak.defer` 打开时，高峰时段不派给 DeepSeek。
    - 没派出去的任务，会写明原因。自动调度一个都没派出去时也保存原因；之后的定时检查结果一样时不再写盘，页面上的时间是这个结果第一次出现的时间。
  - 揭晓、选定、裁决这些决定仍由你做。
- **冷却**：参与者被限流或额度用完时暂停派给它，按参与者记，所有项目共用，重启后仍在。
  - API 被限流（429）：按 Retry-After 冷却，没有就按 `cooldown.apiSeconds`。
  - 命令行 Agent 额度用完或被限流：冷却 `cooldown.cliMinutes`。
- **上限**：派发时超出调用次数或费用上限，任务转“待你决定”，这个项目这一轮不再往下派。已经到了上限时，自动调度一个都不再试（不会把已就绪的任务一个个转进“待你决定”），等你提高上限。
- **轮与停滞**：一轮 = 一批派发到全部结束（密封任务交稿、等你揭晓也算结束）。收轮时程序比对正式内容、计算质量指标，分别记录：
  - 有没有填改动记录：只是辅助信号，不算停滞；
  - 内容有没有变化：只换了版本号、正文没变，不算变化；
  - 质量指标有没有提升：新增 supported 论断、解除阻塞、观众型读者标出的不懂处变少。
  - 结论为：有进展、内容没有变化、有变化但没提升、没有任务完成、只有读者或评审。
  - 连续 `plateau.rounds` 轮停滞时按 `plateau.action` 处理：派观众型新读者读当前作品，或交给你决定。
- **改动记录**：读资料任务可以交 `{"changes":[…],"changelog":[{"id":"C003","type":"fix","note":"…"}]}`。type 取 evidence / fix / clarity；新建记录写临时编号。晋升后换成正式编号，记在 `<项目>/changelog.jsonl`。
- **阶段**：七步流程（明确目标、收集来源、抽取论断、大纲、讲稿、幻灯片、审阅），由你在“调度”页切换。切换时：
  - 程序从正式记录生成一页以内的交接单（`<项目>/handoff/H###.md`，不调用模型，不写内容生产者的身份）；
  - 旧阶段的工作记忆先归档再清空，新阶段换一个记忆空间（工坊·项目名·阶段名）；
  - 新阶段的读资料和起草任务包带上这份交接单，不带此前的讨论；观众型读者和匿名评审不带。
  - 一轮还没收轮时不能切换。
  - 切换中途失败（例如磁盘写满）：阶段不变，“调度”页和“待你决定”里显示没做完的切换和旧阶段笔记的归档位置。再切换一次到同一个阶段（重启后也可以）就从头重做：交接单原样重写；旧笔记若已归档、清空，重做时把空间里现有的笔记合并进同一份归档，不会再归档一份空的。没做完之前，不能切到别的阶段，调度也暂停派发。
- **研讨**：挂到项目上的议题，记忆默认用这个项目当前阶段的空间。讨论太长需要截断时，用“项目约定＋当前交接单”代替开题帖，加上被省略部分里的表决结果（决议摘要）和最近的发言。截断后的总长不超过 `maxPromptChars`：背景最多占 35%，决议摘要最多占 20%（最多 3 条，每条只留开头，注明全文在第几楼），其余给最近发言；最近一条发言总会出现，太长时只留开头。
- 流程状态在 `<项目>/workflow.json`，冷却记录在 `projects/_cooldowns.json`，都由服务维护、不进 git。

## 导出与成品检查（WP7a）

- **幻灯片源**：`slides/` 下每页一条记录（title、body、notes、order、claims）。正文的约定：
  - 每个句子要么带论断编号，要么标为非事实。
    - 编号写 `C001`，可以单写，也可以写在〔〕［］[]（）() 里；几个编号用顿号或逗号隔开。
    - 非事实写 `〔非事实〕`，放在句首或句尾。
  - 编号必须在这一页的 `claims` 里，按那里写的版本绑定。
  - `- ` 开头的行是要点，缩进两格是下一级。
- **导出**（“导出”标签页，`POST /export`）：
  - 格式有 Markdown 和 PPTX，可以选一种或两种。
  - 编号从页面上去掉：PPTX 里挪进讲者备注（“依据”加上一行 `〔SL001@2 · 依据 C001@1〕` 标记），Markdown 里写成脚注，文末列出每条论断的原文与出处。
  - 每次导出写成一条导出记录 `EX###`，只由导出流程经提交入口写入。记录里有：用了哪些幻灯片（哪个版本）、模板和 skill 的内容 hash、版式方案、生成的文件（存成 blob，随 git 留档），以及检查结果。
  - 幻灯片改版后，导出变成“待更新”，要重新导出。
  - `<项目>/exports/EX###/` 下的文件是副本和渲染产物，不进 git。
- **导出方式**（`export.via`）：
  - `script`：脚本直接生成。
  - 参与者的 id：派给这位 Agent 出版式方案。Agent 不拿工具，只按幻灯片、模板的版式清单和 skill，回一份 JSON（每页用模板里的哪个版式）。脚本照方案生成，检查一样。
- **模板与 skill**：
  - `export.template` 写 `templates/pptx/` 里的文件名，默认 `default.pptx`（16:9，中文用微软雅黑，西文用 Segoe UI；由 `lib/workbench/export/make_template.py` 生成）。
  - `export.skill` 写 `templates/skills/` 里的 Markdown 文件名，例如 `简洁版式.md`。
  - 换模板或 skill 不用改代码；只认文件名，写路径会被拒绝。
- **结构检查**（程序，导出时做）：逐句检查论断编号或非事实标记；编号要在 claims 里；引用的论断要全部可进入成品且是当前版本；正文字数不能超过 `slides.maxCharsPerPage`；讲者备注不能为空。
- **读回核对**（导出 PPTX 时做）：读回生成的 PPTX，核对页数、每页的标题与正文、备注，以及备注里的标记（页序、版本、论断编号）。
- **渲染检查**（导出详情里点“做渲染检查”）：
  - 用本机 PowerPoint 在后台把 PPTX 转成 PDF 和逐页 PNG，读出每个文本框的实际排版范围。
  - 程序查文字溢出（超出文本框或页面）、文字重叠、本机没有的字体（对照本机字体的各语言名称）、图片变形（显示的宽高比和原图不一致）。
  - 有图表的页面提示看图确认标签。
  - 结果写成导出记录的新版本。没有 PowerPoint 时只查字体、图片和图表，溢出与重叠记为“未检查”。
  - `render.engine` 为 `libreoffice` 时报错：本机没有安装，这一版没有接。
- **逐页视觉检查**（WP7b，导出详情里）：
  - **模型初查**：派一位能看图的参与者（这一版只接 Claude；通用适配器也行），每次调用最多 8 页。
    - 它不拿工具，只拿到每页的文字、程序查出的问题，以及每页的截图（作为图片附上）。
    - 它逐页回 pass / fail 和问题（溢出、重叠、字体、图表、图片、看不清、其他）。
  - **你终审**：逐页点“通过”或“不通过”。不通过时必须写一句说明。
  - **检查记录**：每页每次一条渲染检查记录 `RC###`，只增不改。
    - 改判就再审一次，以最新的为准。
    - 记录指向导出的版本、那次渲染、那一页和那张截图；截图随记录进 git 留档。
    - 重新渲染（导出升版）后，旧的检查不再算数。
- **可交付**：以下条件同时满足：
  - 用到的幻灯片仍是当前版本；
  - 导出时的结构检查、读回核对都通过；
  - 此刻再查一遍结构也通过（导出之后新增阻塞异议、新的核验，不改版本也会反映出来）；
  - 有 PPTX 时，渲染检查通过，并且每一页都经你终审通过。

## 试运行报告（WP7b）

“报告”标签页（`GET /report`，可以下载 Markdown）把多 Agent 版和单 Agent 基线（`<项目>/baseline.md` 的“指标”表）逐项对比：

- **核心论断可追溯到有效证据的比例**（程序算）：成品引用的核心论断（`core: true`）中，可追溯的条数。没有标核心的，就按成品引用的全部论断算。可追溯要同时满足：
  - 引用的版本仍是当前版本；
  - 论断可进入成品；
  - 每条引文都能在来源的正文快照里找到。
- **发现的实质错误数**：你在页面上填写抽查结果。程序另列流程中拦下的问题（成立的阻塞异议、核验判为不支持的次数）作参考。
- **你的修改时间**：你填写。
- **总用时**（程序算）：从项目第一次提交，到成品可交付（最后一页终审）。
- **API / 订阅额度花费**（程序算）：用量账本里的调用次数、API 费用，以及每位参与者各调用了几次。

报告用的是最新的可交付导出；没有可交付的导出时，就用最新的导出并注明。你填的数值存在 `<项目>/trial.json`，不进 git。

## 用命令行新建项目

页面上用“＋ 新建项目”向导（见上文）。也可以用命令行：

```bash
npm run new-project 项目名
```

服务在运行时，脚本经由服务接口创建；连不上服务时先取项目目录的锁，取得到才在本地创建（取不到说明服务还活着，直接报错）。新项目包含 `project.md`（项目约定）、`protocol.json`（对默认参数的覆盖）、`baseline.md`（单 Agent 基线记录）和固定的子目录。模板在 `templates/project/`。

`projects/` 下没有 `project.md` 的目录（例如原始资料文件夹）不算项目，接口和列表都会忽略它们。

## 参数

可调参数的默认值在 `workbench.defaults.json`，项目用自己的 `protocol.json` 覆盖，只写要改的键（可以在页面上改，见上文“新建项目与项目约定”）。含义见开发文档“配置文件”一节。补充说明：

- `rounds: null` 表示沿用 WeTalk 现有的讨论与表决轮次设置。
- 以 `_` 开头的键是备注，合并时忽略。
- `modes` 和 `routing` 允许项目新增键；其他位置写了未知的键会报错，避免拼错的参数被悄悄忽略。
- 调用次数、API 费用、任务深度、尝试次数、补证次数、重试次数和租约时长是系统不变量：必须是有限的数字，不能删掉或设为无限。

## 运行依赖

目前没有 npm 运行依赖。需要本机已安装：

| 依赖 | 用途 |
| --- | --- |
| Node.js 18+ | 服务与测试 |
| git | `projects/` 的自动留档（不可用时数据照常提交，只是没有留档） |
| DeepSeek API | 对话、Search、Fetch（Node 自带 fetch，没有 npm 依赖）；需要环境变量 `DEEPSEEK_API_KEY` |
| Python 3 与仓库里的 `.venv` | 导出 PPTX：`lib/workbench/export/pptx_export.py` 用 python-pptx 套模板生成并读回核对。安装：`py -3 -m venv .venv`，再 `.venv\Scripts\python.exe -m pip install -r requirements-export.txt`（python-pptx 会带上 lxml、Pillow、XlsxWriter）。路径由 `export.python` 指定 |
| Microsoft PowerPoint（可选） | 渲染检查：`lib/workbench/export/render.ps1` 经 COM 自动化，只读打开、不显示窗口；你自己开着别的演示文稿时不会退出 PowerPoint |

## 测试

```bash
npm test
```

工坊模块的测试在 `tests/workbench/`，每个测试在临时目录（路径含中日文字符）里建样本项目。

```bash
WB_REAL_RENDER=1 node --test --test-name-pattern=真渲染 tests/workbench/wp7.test.mjs
```
