## R1 · P1 · 新增阻塞异议后，已有导出仍显示“可交付” → 已修复

- **原因**：可交付只看导出时存下的结构检查和版本新鲜度。新增异议、新的核验不改论断和页面的版本，导出仍是 current，可交付就不会变。
- **修法**：列表和详情每次都按此刻的派生状态，把导出用到的幻灯片再做一遍结构检查（`live`）。可交付改为同时满足以下几条：
  - 导出仍是 current；
  - 导出时的结构检查通过；
  - 此刻的结构检查也通过；
  - 读回核对通过；
  - 有 PPTX 时，渲染检查通过。
- **检查结果怎么存**：导出时存下的检查结果不改（历史快照）。“此刻”的结果不存进记录，每次读取时算出来。所以异议撤回、核验恢复后，可交付自动恢复。
- **性能**：列表一次取完全部记录（`recordsOf`），所有导出共用这一份。结构检查本身也改为用这份记录表，不再逐条 `getRecord`。

## R2 · P2 · 英文句号没拆句，没标注的句子能借后一句的依据 → 已修复

- **拆句**：
  - 中文句末标点（。！？；）一律断开。
  - 英文的 `. ! ? ;` 只在后面跟空白或到段末时断开，所以 `1.5`、`a.b` 不断。
  - 句点前是常见缩写（e.g.、i.e.、etc.、vs.、cf.、Mr.、Dr.、Prof.、No.、Fig. 等）或单个大写字母时，也不断。
  - 句末标点后面紧跟的右引号、右括号算这一句。
- **正则转义**：你指出的问题确认属实。模板字符串里的 `\s` 变成了字母 `s`，所以句末标点后面有空格时，编号归不回前一句。已改为 `\\s`。
- **逐句检查**：每句分别要有编号或非事实标记，后一句的编号或标记不再替前一句担保。〔非事实〕可以写在句首（属于这一句），也可以写在句末标点之前或段末（属于前一句）。
- **回归**：
  - 你的两种绕过，都只报第一句没标注。
  - `人口是1200。 （C001）〔非事实〕谢谢。` 不再误报。
  - `Growth was 1.5 times, e.g. apples (C001). Dr. Smith agrees C002. Thanks〔非事实〕.` 通过。
  - `Fact one C001! Is it true? 〔非事实〕Yes; really C002.` 只报 `Is it true?`。
  - 右引号跟在句号后面时，算前一句。

## R3 · P2 · 旧版本引用配上新版论断正文，追溯信息错误 → 已修复

- **新接口**：提交入口加了 `recordVersion(项目, 编号, 版本)`。当前版本读正式文件，旧版本读归档副本，和追溯用的是同一个读取函数。
- **导出取依据**：一律按引用的版本取：
  - 论断按页面 claims 里的版本；
  - 来源（标题）按论断 sources 里的版本；
  - Markdown 的脚注、PPTX 讲者备注里的“依据”都一样。
- **还原不出时**：某个版本在正式记录和归档里都没有，就拒绝导出（409，写明是哪个编号、哪个版本），不拿当前版本顶替。生成任何文件之前先检查。
- **脚注键**：Markdown 的脚注键带上版本（`[^C001@1]`），同一论断的不同版本不会合并覆盖。
- **回归**：
  - SL001 继续引用 C001@1；C001 改成 v2（正文 `NEW-CLAIM…`），S001 也改成 v2（标题 `NEW-TITLE…`）。
  - 导出 md 和 pptx：结构检查照常不通过，但 Markdown 脚注是 `[^C001@1]: C001@1 没有证据表明 A 导致 B —— 某书：…`，PPTX 读回的备注依据也是旧正文，两个文件里都没有 `NEW-CLAIM`、`NEW-TITLE`。
