## 二轮 R1 · 排在队首之后的请求不能及时超时或取消 → 已修复

`createRateLimiter` 改为显式的先进先出等待队列：

- 每个等待者从排队那一刻起就监听自己的 `signal`。被中止（总时限、“停止”）时立即从队列里移除并拒绝，不需要等前面的人。
- 离队的节点永远拿不到名额，也就不会占预算名额、不会发请求。其余等待者的先后顺序不变。
- 发放名额由一个 `pump()` 完成：把 1 秒前的记录移出窗口，按顺序发放剩余名额；还有人在等就定一个到“最早那次满 1 秒”的定时器。可以注入 `schedule`（假时钟测试用）。

回归用例（`deepseek.test.mjs`，“二轮 R1”）：

- 用与生产相同的每秒 5 次限速器，先用完 5 个名额，再放一个队首等待者。之后发起的请求：`timeoutMs=50` 时不到 300ms 就返回 timeout；被 AbortController 中止时也在 300ms 内返回。两者都没有发出请求。
- 队首拿到名额之后，紧接着排队的人在同一个窗口里马上拿到名额，说明离队的节点没有占名额；队列清空。
- 原来的假时钟用例改用 `schedule` 注入。

你的复现脚本：`elapsedMs` 从 1013 降到 **56**，`sent: 0`。

## 二轮 R2 · 正文断连后退避变成零 → 已修复

`(res && !networkError && retryAfterMs(...)) ?? 配置间隔` 在正文断连时会得到 `false`，而 `??` 不会把 false 当作缺省。改为先算出 `fromHeader`：只在完整收到的响应上读取 `Retry-After`，读不到时为 `null`；然后 `wait = fromHeader ?? 配置间隔`。`waitMs` 一定是数字。

回归用例（“二轮 R2”，真实本机 HTTP）：200 和 503 两种响应头之后正文断连，配置 `delaysSec: [0.3]`。两种情况下 `waitMs` 都是数字 300，两次请求实际相隔 ≥ 290ms。保活后断连、坏 JSON、超时、中止的旧用例都保留。

你的复现脚本：`actualWaitMs` 从 false 变为 **300**，`requestGapMs` 为 340。

## 二轮 R3 · 迁址失败把新地址的失败算给旧来源地址 → 已修复

可获取性按“来源卡当前（已提交）的地址”过滤：

- 用量账本里每次抓取本来就记着实际地址 `url` 和 `source_id`（迁址抓取另带 `relocate: true`）。`availabilityOf(project, { urlOf })` 只认 `url` 与来源卡当前地址相同（URL 规范化后比较）的抓取。
  - 迁址失败：来源仍指向 A，B 的失败不算 A 的；
  - 迁址抓取成功但晋升冲突：来源仍指向 A，B 的成功不算 A 的；
  - 迁址成功：来源改指向 B，之后只认 B 的结果；迁址前在途的 A 请求即使晚到，也不算 B 的。
- 主持人的确认（gone / available）同样带上确认时的地址（HTTP 路由取当时来源卡的 url），只对该地址有效。第一版没有地址字段的确认对任何地址都有效（兼容）。
- `urlOf` **必须给**，漏传直接报错，不会悄悄退回“不按地址过滤”。提交入口在 `getRecord` 和追溯里用已提交快照的地址调用它。`server.mjs` 的接线是 `(p, urlOf) => usage.availabilityOf(p, { urlOf })`。
- Web 层的失败详情改从 `gateway.getRecord()` 取可获取性，与界面一致。

回归用例（“二轮 R3”）：

- A 可用时迁往 B 得到 404：S001 仍是 v1、地址 A、available；账本最后一行是 B 的失败（保留，用于排错与记账）。
- 迁往 B 抓取成功、但晋升被拒（409）：S001 仍指向 A，状态不受 B 影响。
- 迁址前发出的 A 慢请求，在迁址成功之后才返回：S001 指向 B、available。
- 之后 B 失败：S001 变为 temporarily_unavailable。
- 针对 A 的 gone 确认不影响已指向 B 的 S001；针对 B 的确认生效。
- 另外，第一轮 R2 的用例改为通过提交入口读取可获取性。

你的复现脚本：因为 `urlOf` 现在是必填，脚本里 `availabilityOf: (p) => usage.availabilityOf(p)` 的接线和直接调用 `legacyUsage.availabilityOf('legacy')` 会按设计报错。这两处补上 `urlOf` 后重跑：迁址失败前后都是 **available**，地址 A、版本 1，失败记录的地址是 B。

## 二轮 R4 · 旧格式账本被静默忽略 → 已修复

加载时兼容第一版的单行格式（没有 `phase`）：每行按一次**已结算**的尝试计数和计费，以行号生成稳定 id（`legacy-<行号>`），标 `legacy: true`。只读兼容、不改写文件，重启多少次都不会重复计数。新旧格式混合的文件按行累加。

回归用例（“二轮 R4”）：

- 两行旧格式（一次成功 $0.001、一次 404）加上新格式的一次 Fetch，连续加载两次：调用次数都是 3、费用都是 0.00175，旧格式 2 条；已到 3 次上限，再占名额被拒。
- 只有旧格式两行时：可获取性为 temporarily_unavailable（最后一次是 404），合计 2 次、$0.001。
- 不给 `urlOf` 时报错。

你的复现脚本：`calls 2、usd 0.001、historicalEntries 2、availability temporarily_unavailable、extraAllowed false`。
