## 2. 值得重点看的设计点

1. **新建项目的原子性。** 先在 `projects/_staging-<随机>/` 建好整个目录（子目录、模板文件、`events.jsonl` 里的 `project_created`），校验模板的 `protocol.json` 合法后再一次 `rename` 到位（遇到 EPERM / EBUSY / EACCES 时退避重试，最多 8 次，见 `lib/workbench/fsx.mjs`；WP2 的写前日志会复用它）。中途崩溃只会留下以 `_` 开头的临时目录，列表会忽略它（`projects/.gitignore` 也忽略 `/_staging-*/`）。目前没有启动时清理残留临时目录的逻辑，打算在 WP2 的恢复流程里一起做。
2. **git 留档只提交本次路径。** `commitPaths()` 先 `git add -- <paths>`，再 `git commit -m … -- <paths>`。测试里预先暂存了一个无关文件，确认它没有被带进提交、提交后仍处于暂存状态。git 失败时不抛出，只在 `events.jsonl` 记 `archive_failed`；重试队列是 WP2 的内容。
3. **projects 仓库强制 `core.autocrlf=false`。** 本机全局是 `autocrlf=true`。契约二的恢复要按 hash 比对正式文件与清单，留档必须逐字节一致，所以 `ensureRepo()` 每次都在仓库级关掉换行转换。
4. **参数合并的规则。**
   - 以 `_` 开头的键视为备注，忽略（模板的 `protocol.json` 用 `_comment` 说明用法）。
   - `modes`、`routing` 允许项目新增键（新任务类型），其他位置的未知键报错，防止拼错的参数被悄悄忽略。
   - 类型必须与默认值一致；默认值为 `null` 的键（`rounds`、`export.template`、`export.skill`）不限类型。
   - `projectsDir` 只能全局设置，项目覆盖会报错。
   - 系统不变量（不可关闭）：`budget.calls`、`budget.apiUsd`、`task.maxDepth`、`task.maxAttempts`、`evidence.maxAttempts`、`retry.max`、`lease.minutes` 必须是有限数字；计数类必须是整数；`retry.max` 可以为 0，其余必须大于 0。
5. **项目名校验。** 项目名直接用作目录名和 URL 路径段：允许中日文和空格；拒绝路径分隔符、Windows 保留字符与保留名（CON、NUL.txt 等）、以 `.`/`_` 开头（留给 `_txn` 等内部目录）、以空格或句点结尾、超过 64 字。
6. **哪些目录算项目。** `projects/` 下只有含 `project.md`、且不以 `.`/`_` 开头的子目录才算项目。主持人原有的资料文件夹 `交感巫术`、`创世物语` 因此不受影响，也没有被纳入 projects 仓库的提交（保持未跟踪）。
