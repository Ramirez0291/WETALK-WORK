## 0. 设计上的取舍

- **起草者只出草案，不派发**。设计的核心原则是“调度只执行规则，不调用模型做派发判断”，独立性也靠程序保证（核验者与作者不同厂商、竞争起草密封）。如果让一个 Agent 既规划又派发，它就能决定谁核验谁，这些保证就失效了。所以方案一只做到：
  - 把你的一段说明整理成约定的各节；
  - 列出要你确认的问题和建议先搜的关键词。
  
  你在页面上改过、确认后才生效。之后的任务照常按分工表由规则派发，核验者照常由规则挑选。
- **首页不新增流程**。首页上每个按钮调用的都是各页原来的同一个接口（`/web/fetch`、`/submissions`、`/divide`、`/claims/:c/verify`、`/compete`、`/phase`、`/export`），规则、上限、身份检查都不变，只是按阶段排好顺序、默认值从分工表里取。

## 1. 在页面上改项目约定与参数

- **接口**（都只限主持人）：
  - `POST /conventions`：`{ text, expected }`；
  - `POST /protocol`：`{ override, expected }`。
  - `expected` 是页面读到时文件的 sha256。`GET /api/projects/:p` 新增 `hashes: { conventions, protocol }` 和 `missing`（约定里没填的节）。
- **写入**（`project.mjs` 的 `writeSetting`，经提交入口的同一个队列 `gateway.setConventions / setProtocol`，写入故障时同样拒绝）：
  1. hash 对不上就拒绝（409），不覆盖。包括在服务之外直接改了文件：页面拿着旧 hash，保存被拒，外部改动保留。
  2. 参数先按默认参数合并校验（`resolveConfig`），不合法 400，文件不动。备注键（`_comment`）照写。
  3. 内容没变：返回 `changed: false`，不写、不存档。
  4. 旧版本复制到 `<项目>/archive/versions/_project/<文件>.<时间>.<旧 hash 前 12 位>`（`/*/archive/versions/` 本来就被忽略，不进 git）。
  5. 写临时文件、改名到位。
  6. `events.jsonl` 记 `setting_changed`（文件、旧 hash、新 hash、主持人）。
  7. 按（改后的）项目配置 `git.autoCommit` 留档：`[工坊] 修改 <项目> 的项目约定 / 参数`；失败记 `archive_failed`。
  8. 发 `wb-project` 事件，页面上的项目名跟着更新（标题取约定的第一个 `# `）。
- **已派出的任务不受影响**：任务包里存着当时实际发送的提示词（含约定）。之后派出的任务用新版。
- **页面**（“约定与系统 → 项目约定与参数”）：
  - **约定**：分节编辑器（`public/conventions.js`，服务端和页面共用）。
    - 节 = 二级标题到下一个二级标题，开头加各节首尾相接就是原文。代码块里的 `##` 不算标题，CRLF 也照样往返。
    - 每节一个输入框，模板里的引导语（整行全角括号）作占位提示。
    - 没改过的节原样写回，一个字符都不差；清空一节时放回引导语。
    - 可以切到“直接改 Markdown”。
  - **参数**：8 项常用参数做成表单，改动同步写进下面的 JSON，也可以直接改 JSON。
  - **冲突**：保存被拒时提示，并给一个“载入最新的约定（丢掉你在这里的改动）”的按钮。
- **没填的节**（`missingOf`）：去掉引导语和空的列表项后什么都没有，记为 empty；“页数：”这类键后面没写值，记为 blank 并列出键名。首页和编辑器都标出来。

## 2. Agent 起草约定（`plan_project`）

- **发起**：`POST /plan`：`{ participant, brief }`（只限主持人）。
  - 现在的约定原文（含模板引导语）存成 blob，作为任务输入；`brief` 进任务的 goal。
  - 任务上记 `plan: { base }`，是起草时约定的 hash。
  - 立即派给指定的参与者；派不出去就取消这个任务，并返回错误。
- **限制**：
  - 手动新建这类任务会被拒绝（400），和 `export`、`render_review` 一样；
  - 外部会话不能认领（409），因为交来的是草案，不是提交入口的 changes；
  - 自动调度不派它（和导出版式一样排除在已就绪任务之外）。
- **可见性 `plan`**：输入内联、不给工具。任务包里不再重复一份去掉引导语的“项目约定”，输入里已经有原文。
- **输出要求**（`draft.mjs` 的 `DRAFT_OUTPUT`）：
  - 只写说明里有的，或从中直接推得出的；拿不准的写成要你确认的问题。
  - 不编造来源、数字或事实。约定只写要求，不写内容本身的结论。
  - 节标题只用约定里已有的；验收标准是通用要求，没另提要求时不写。
  - 格式：`{"sections":{节标题: 正文}, "questions":[…≤5], "queries":[…≤8]}`。
- **解析**（`parseDraft`）：
  - 没有 json 代码块、结构不对、没有一节对得上约定：这次尝试失败，写明原因（照常重试，直到尝试次数用完）。
  - 对不上约定的节名放进 `ignored`，页面上列出来，不合并。
  - 合格时按任务输入里那一版约定合并（`mergeSections`），结果记在任务上（`completeDirect`）。草案不进正式区，也不写进 `project.md`。
- **查看**：`GET /plan` 返回最近一次起草的任务、草案和 `stale`。之后约定被改过（包括你已经确认），`stale` 为真，首页不再提示“待确认”。

## 3. 新建项目向导

- 右上角“＋ 新建项目”；还没有任何项目时，打开页面就是向导。
- **第一步**：项目名、一段说明、起草者（默认上次选的，没有就第一位 Claude）。
  - “新建并起草约定”：建项目，再 `POST /plan`。起草派不出去时项目照样建好，进入第二步，在那里重试或自己填。
  - “新建，我自己填”：只建项目。
- **第二步**：
  - 草案在路上时显示“起草中”，可以取消。
  - 草案到了：按节合并进编辑器，起草者写的节标“草案”，它的问题列在上面。如果你已经在编辑器里改了，草案到达时不覆盖，只给一个“换成刚到的草案”的按钮。
  - “确认约定，开始收集来源”：保存约定（还有没填的节时先确认）。阶段还没开始（或在“明确目标”）时切到“收集来源”，回到首页。
  - “只保存，稍后再开始”。
  - “重新起草”：改说明、换起草者再派一次。

## 4. 首页“下一步”与分组导航

- **导航**：两级。
  - 组：首页 / 工作 / 资料 / 成品 / 约定与系统。
  - 组里的页：首页（下一步、待你决定）；工作（任务、分工、竞争、调度与阶段）；资料（记录、追溯、研讨）；成品（导出、报告）；约定与系统（项目约定与参数、提交与留档、候选稿）。
  - 原来各处 `#tabs [data-tab=…]` 的跳转照常可用，会切到对应的组。待你决定的条数显示在“首页”组上。
- **首页**：
  - 项目名和七步阶段条；
  - “下一步”卡片（每个阶段能做的事见 README“首页：下一步”）；
  - 待你决定的前 5 项；
  - 约定填了没有（没填的节列出来）；
  - 进展统计。
- **几个细节**：
  - 派对抗核验：只派还缺核验、是最新版本、没有核验任务在路上的论断，连点两次不会重复派。
  - 抓取：没抓到的网址留在框里，报错逐条列出（这台机器上没有 `DEEPSEEK_API_KEY`，界面检查时走的就是这条路）。
  - 手工录入来源卡：标题、正文快照必填，出处和网址至少一个（和提交入口的规则一致）。
  - 实时刷新：你正在首页或设置页的输入框里打字时不重画；重画时保留没提交的输入和展开的折叠块，换了阶段就不保留（表单整个换了）。
  - 并发：新建项目时，接口返回和实时事件各触发一次加载。现在只认最后一次；首页、向导、设置页在等待期间换了项目时，丢弃这次的结果。
- **英文**：新增 163 条界面文字的英文（`locales/en.js`）。服务端的报错和原因照旧不翻译。

## 7. 已知限制，请重点看

1. **幻灯片阶段没有自动化**：首页只能引导你去候选稿录入。把讲稿拆成幻灯片记录需要一个新的任务类型（读讲稿、按页出 slide 记录），这次没做。
2. **起草只用于约定**：草案里的“建议先搜的关键词”只在“收集来源”那一步做成一键搜索，不会自动建任务。
3. **首页的默认参与者**：取分工表（routing）里对应工作类型的参与者，按 id 或适配器匹配。分工表里没有可用的人时没有默认勾选，要你自己勾。
4. **只看最近一次起草**：`GET /plan` 只返回最近的那个起草任务。重新起草之后，旧草案只能在“任务”页的任务包里看。
5. **项目约定的历史**：git 里有每次修改，`archive/versions/_project/` 里有旧版本副本；页面上暂时没有“历史版本”列表。
6. **约定里的总标题**：分节编辑时不能改；要改总标题（也就是项目在列表里显示的名字），切到“直接改 Markdown”。
