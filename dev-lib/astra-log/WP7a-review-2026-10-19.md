## R1 · P1 · 新增阻塞异议后，已有导出仍被标记为可交付

位置：`lib/workbench/exports.mjs:267–277`，尤其是 `deliverable` 的计算。

当前只检查版本新鲜度和导出时保存的结构检查结果。新增针对当前论断的阻塞异议不会改动该论断或幻灯片的版本，所以导出仍然是 `current`；但实时论断/幻灯片已不可进入成品。历史检查通过不能代替当前的成品准入状态。

独立复现：建立 S001、C001@1、SL001@1，完成独立 supported 核验，导出 Markdown EX001，此时 `deliverable=true`。随后新增针对 C001@1 的 open/number_error 异议 O001。实际得到：

```text
EX001.freshness = current
SL001.status.ready = false
C001.status.blockers = [O001]
EX001.deliverable = true
此时重新生成 EX002，deliverable = false
```

同一份内容，仅因为是否重新导出而呈现相反的可交付结论。该计算也用于 PPTX；本轮独立端到端复现使用 Markdown。新核验改变当前准入状态而不改论断版本，也应纳入回归范围。

建议保留历史检查快照，同时在列表/详情的可交付判定中检查所有引用页面及论断的当前准入状态。新增/解除阻塞异议、核验结果变化后，要能正确撤销或恢复可交付，不能只依赖版本变更。

## R2 · P2 · 英文句号未拆句，前一句能借用后一句的依据或非事实标记

位置：`lib/workbench/export/deck.mjs:36–39`。

`sentencesOf()` 的分隔符没有英文句号，因此同段英文陈述被当作一句。结构检查只要在整段找到一个编号或一个 `〔非事实〕` 就通过，违背每句话分别标记的约定。

以下两个样本均实测 `structure.ok=true`、没有问题项，但第一句都没有依据或非事实标记：

```text
An unsupported factual sentence. Population is 1200 C001.
An unsupported factual sentence. 〔非事实〕Welcome.
```

同一解析器还有反向误报：第 36 行 RegExp 使用模板字符串，`\s` 没有双重转义，实际不是空白匹配。合法的 `人口是1200。 （C001）〔非事实〕谢谢。` 被判第一句缺编号；中间的空格阻止句后编号归回前一句。

建议补全英文句子边界处理（注意小数、缩写），将非事实标记和编号约束到各句，修正 RegExp 字符串转义。补上述绕过和空白误报的回归，不能仅增加中文标点样本。

## R3 · P2 · 旧版本引用配上最新版本正文，导出依据与版本号不一致

位置：`lib/workbench/exports.mjs:168–173`；调用点包括 Markdown 的 `claimInfo` 和 PPTX 的 `claimText`。

`claim(ref)` 忽略 `ref.version`，始终获取当前记录。导出允许结构检查失败的诊断成品，因此 stale 引用并不会阻止这个错误内容进入可下载文件。

独立复现：SL001 继续引用 C001@1；把 C001 更新为 v2，正文改为 `NEW-CLAIM Population must be corrected.`，然后导出 Markdown。文件实际脚注为：

```text
[^C001]: C001@1 NEW-CLAIM Population must be corrected. —— Fixture：“1200”
```

这把 v2 正文标记成了 v1 依据。该导出的结构检查确实失败、不可交付；问题不是它被错误放行，而是导出文件自身提供了错误的版本追溯。PPTX 的备注依据也使用同一个当前版本读取器（本轮文件内容复现为 Markdown）。来源标题也通过相同 helper 读取当前记录。

建议按引用版本读取归档快照，或者明确拒绝生成无法正确还原的版本；不要用最新正文冒充旧版本。若支持同一论断的多个版本同时导出，Markdown 脚注键也需包含版本，避免按 ID 合并覆盖。补修改论断后导出旧引用的文件内容核对。

## R4 · P2 · 文本框溢出只比较右边和下边，漏掉左侧与顶部

位置：`lib/workbench/export/render.mjs:64–67`。

`overflow` 仅比较 boundRight/boundBottom，没有比较 boundLeft/boundTop 与文本框左/上边界。`off_slide` 只能兜底超出整张页面的文字，无法发现仍在页面内、但越过自身文本框的文字。

独立几何样本：文本框 `(left=200, top=200, width=100, height=100)`，文字实际范围 `(160,160,140,140)`。文字向左/上各超出 40pt，整个范围仍在页面内；分析结果却为 `ok=true`、没有问题项。

真实 PowerPoint 也已确认：在默认模板的空白版式中创建 100×100pt 文本框，位置 `(300,200)`；20pt Segoe UI、右对齐、不换行、关闭自动缩放、右边距 12pt，文本为 16 个 A。COM 实测文字左边界为 182pt、宽 211.5pt、顶边界 200pt、高 24pt，即向左越框 118pt、右端仍在框内。分析结果 `ok=true`、`issues=[]`。首次零右边距样本同时向右越框 5.5pt，已有检查能捕获；增加正常右边距后隔离出仅左侧溢出的漏检，并非未验证的假设。

建议同时比较四个方向并保留 2pt 容差，补右对齐不换行文本向左溢出、顶部溢出以及恰好位于容差内的回归。程序溢出检查属于 WP7a，不应等 WP7b 的视觉检查来弥补。
