## R1 · P1 · 同一参与者换厂商后，作者集合丢掉后续身份，仍会放行同厂商核验

位置：`lib/workbench/commit.mjs:405–407`；消费方为 `lib/workbench/verify.mjs:35–37`、`87` 及核验写入、派发、异议裁定的统一 eligibility 检查。

当前合并把旧作者放在前面，然后按 actorKey（主体类型＋参与者）只保留第一次出现的条目。如果同一参与者换用另一个厂商的模型，后续真实贡献者身份会被整个丢掉。authorsOf 在已有非空 authors 时，又不再参考当前 provenance。

独立探针 `new-R1-author-vendor-change` 通过真实任务栅栏与提交入口复现：

1. 参与者 `writer` 使用 generic / `deepseek-fixture` 起草 C001 v1。
2. 同一个 `writer` 换为 generic / `gpt-6-fixture`，改写并提交 C001 v2。
3. 另一位 Codex/openai 参与者对 v2 提交 supported 核验。

实际结果：

```text
C001.provenance.vendor = openai
C001.authors = [{ participant: writer, vendor: deepseek, ... }]
核验没有被拒绝
verification = supported, independent = 1, enough = true
ready = true
```

此例不需要伪造身份，也没有配置/报告冲突：是同一参与者在两次任务中正常换模型。当前版作者明明来自 openai，却被当成只有 deepseek 作者。由于核验计数、派发和裁定共享该集合，都会受到影响。反向换模型同理；首次厂商 unknown 后变为已知，也会一直保留过时的 unknown。

本轮批准的“作者集合只增不减”取舍可以采用，但“按参与者去重”不能等于只保存该参与者第一次的模型/厂商。它必须保留各次贡献所带来的独立性约束。

建议：同一主体可以聚合显示，但底层保存其各次贡献的厂商/身份依据，资格判断检查完整集合；或使用能保留不同贡献身份的去重键。不能简单改成保留最后一项，否则会反过来丢掉早期厂商约束。当前 provenance 与历史贡献之间也要保持一致。

补测：同一参与者 A 厂商 → B 厂商改写后，A、B 的其他参与者都不能独立核验/裁定；第三厂商正常通过；厂商从 unknown 变为已知时按批准的保守历史规则明确处理。

## R2 · P2 · 新增 authors 字段进入匿名评审任务包，泄露作者身份

位置：`lib/workbench/packets.mjs:44–46`。字段由本次修复在 `lib/workbench/commit.mjs:407` 写入；匿名处理位于 `lib/workbench/runner.mjs:72–82`。

contentOf 只剔除 provenance、commit、updated_at，新系统字段 authors 留在 rest 中，被序列化为任务输入。后续匿名化只按当前参与者名单和已知厂商词替换，不会结构化移除作者字段。主持人姓名和已移出配置的参与者不在该名单里，扫描也检查不出。

独立探针 `new-R2-anonymous-author-metadata`：

1. 主持人 `review-host` 写一份正文不含署名的大纲 OL001。
2. 创建 anonymous_review，输入 OL001@1，派给假 Claude 评审者。
3. 捕获实际传给 runAgent 的完整提示词。

实际：

```json
{
  "taskState": "submitted",
  "promptSent": true,
  "containsHumanName": true,
  "containsAuthorsField": true,
  "containsHumanKind": true
}
```

这不是正文里偶然提到一个名字，而是系统附加了结构化作者信息。模型收到提示词时就能看到作者是人类及其姓名，违反契约四的匿名评审要求。匿名评审任务类型已经由 WP4 提供；本次新增字段造成的回归不能因为完整竞争流程在 WP5b 而推迟处理。

建议：在任务输入序列化/匿名上下文边界，结构化剔除内容生产者的作者集合及相关身份元数据。现有正文署名替换可继续作为补充，不能作为系统身份字段的唯一屏障。来源卡的文献 author 与内容生产者 authors 含义不同，不要误删正常书目数据。

补测：主持人作者、不在当前配置中的旧参与者、多位作者、实际报告模型字段；捕获最终提示词确认系统作者身份均未进入，同时服务端映射和归档仍可追溯。
