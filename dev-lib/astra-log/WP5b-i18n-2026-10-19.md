## 1. 改了什么

**页头加语言选择。** 和研讨室侧栏一样：`#languageSelect`（`data-no-i18n`），标签“语言”“界面语言”沿用研讨室已有的词条。偏好仍是 `localStorage` 的 `wetalk.language`，两边共用。

**机制全部复用 `i18n.js`。**

- `workbench.js` 引入 `t as ui`，和 `app.js` 用同一个别名。原因是 `workbench.js` 里很多局部变量叫 `t`（任务、议题、追溯结果），直接用 `t` 会被遮住。
- 启动时先 `initStaticTranslations()` 登记 HTML 外壳，再渲染动态内容。
- 动态文字一律用 ``ui`…` ``、`ui('…')` 或 `localized` 包起来。
- `[文字, 样式]` 形式的徽章表（VER、ARCHIVE、O_STATE、TASK_STATE、K_STAGE、P_STATE）用页面里新加的 `localizedBadges`：和 `localized` 一样在取用时翻译，只翻文字，不翻样式。
- 竞争步骤条 `K_STEPS` 的文字在渲染时翻译。

**被标签拆开的句子改成整句。** `t` 会按 HTML 标签切段，所以中间夹着 `<code>`、`<a>` 的句子只能逐段翻译。我把这些标签改成插值传入，这样英文能整句翻译：

- 候选稿说明：原来被 `<code>` 拆成 9 段，现在由 JS 渲染进空的 `#candidateHint`，中文显示与原来一字不差。
- 异议面板“针对 {2}”、落选方案“（任务 {1}）”、“还没有项目……或运行 {0}”。
- 拼出来的词改成完整词条：“揭晓方案 / 揭晓评审”“正式文件在服务之外被删除 / 改动……”“补丁 {0} 已接受 / 已拒绝”。

**其他：**

- 列表分隔符“、”“；”和全角括号、冒号，也按语言切换（英文为 `, `、`; `、` (…)`、`: `）。
- 时间格式按语言用 `en-US` 或 `zh-CN`。
- `api()` 的报错经过 `translateError`：只翻已知的固定句式，其余保持服务端原文。`en.js` 补了 14 条工坊常见的固定报错。
- 切换语言时一起重画这些地方：外壳、项目下拉、当前标签页，以及打开着的记录详情、竞争详情、任务包。
- 任务类型下拉里有“（特殊）”字样，语言变了就重建，并保留当前选择。
- 从记录“开研讨”时自动填的框架文字按界面语言生成，例如“（工坊项目 X 里的论断 C001 第 1 版）”“想讨论的问题：”。记录内容原样带上。
- 候选稿的示例 JSON 按当前语言生成。填进文本框以后就是用户的内容，切换语言不再改它。

**`en.js`：** 新增 394 条，没有改动已有词条。

**中文界面唯一的字面改动：** 异议表单的按钮“提出”改成“提出异议”。原因：`en.js` 里“提出”已经是研讨室的 “Proposed by”，同一个中文词条不能对应两个英文。

**按要求不翻译的：**

- 记录内容
- 方案正文、方案标签（方案甲）和节标题
- 评审意见和退回理由
- 服务端写的任务标题、历史原因，以及“待你决定”里的 reason / error
- 参与者名，包括配置里的“主持人”（研讨室也不翻这个名字）
- 不在固定句式里的服务端报错

## 3. 请你看的地方

1. **标签页和表头共用词条。** “任务”“候选稿”“竞争”“记录”既是标签页名，又是表头，同一个中文只能对应一个英文。我取了复数（Tasks、Candidates、Competitions、Records），当表头读起来略别扭。
2. **标点词条是全局的。** “、”“（{0}）”“{0}：{1}”等目前在研讨室里没有命中。但以后研讨室如果出现同样形状的片段，英文下也会换成英文标点。
3. **切换语言会丢掉没提交的输入。** 切换时会强制重画打开着的详情，里面填了没提交的表单内容会丢。平时的实时刷新会避开正在填的表单，切换语言不避开。
4. **旧问题，没改。** 换项目以后，上一个项目里打开着的详情编号仍会被刷新，可能弹出“不存在”。切换语言时也会刷新它，所以同样可能出现。
